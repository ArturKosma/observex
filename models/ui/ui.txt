# observex: where the game draws its interface (core/UiLayout reads this; tools/ui/make_anchors.py cuts the anchors).
# Screen pixels of the screen it was measured on (2560 x 1440, Lineage 2 Reborn, the user's UI scale).
#
# anchor NAME MIN_SCORE W H from CLIP FIRST LAST X Y [from CLIP FIRST LAST X Y]...
#   A small picture found anywhere on the screen: NAME.pgm (its grey pixels, the mean over frames FIRST to LAST of
#   each clip named, where it sat at X Y, W x H) and NAME-mask.pgm (255 where those pixels never changed: the
#   interface's own drawing; 0 where the world shows through, so it is never compared). Found where the masked
#   pixels match at least MIN_SCORE (correlation, 1 = the same). observex reads only NAME and MIN_SCORE; the rest is
#   for make_anchors.py. Cut it from frames where it stays put and the camera moves, or from two places with
#   different backgrounds, else the world behind it counts as its own.
# piece NAME X0 Y0 X1 Y1 at ANCHOR AX AY
#   A piece of the interface: wherever ANCHOR is found, a piece NAME whose rectangle sits where X0 Y0 X1 Y1 (just
#   past the last pixel) sat when ANCHOR was at AX AY, on the same image.
#   Indented lines under it stretch a side to another anchor on that image, e.g. "right resize-corner 417 824": the
#   nearest resize-corner to the right on the same row (within 3 pixels) moves the piece's right side with it, so a
#   resized window is covered. Sides: left, right (same row), top, bottom (same column); "right?" if it may be missing
#   (then the side stays as measured), otherwise the piece is only there when it is found, or hidden: a framed window
#   begins across the way it was looked for, at most the piece's measured size past where the side was measured
#   (then the side ends where that window begins: the piece's visible part). A search stops at the next ANCHOR of the
#   same piece that way (the next window's corner). The side's anchor is looked for as far from the piece's nearer
#   edge as when measured (a bottom corner stays with the bottom). Several lines for one side are tried in order: the
#   first found sets it (the chat's top-right corner, else its bottom-right one); put a bottom line first if a right
#   one sits at the bottom. "right line" stretches the side to the nearest frame
#   line that way instead (a 1-pixel light line as framed windows have, along the piece for 40 pixels or more, at
#   least 40 pixels from the other side), for an edge that is a frame line where no anchor holds (the target window).
# Framed windows (a 1-pixel light line with darker pixels on both sides, all round, e.g. Map, Skills, Quest) need no
# line here: observex finds them by their frames.
